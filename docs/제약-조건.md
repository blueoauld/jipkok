# 제약 조건

집콕 전체의 형식 규칙, 한도, 보존 기간, 스케줄, 시스템 상한을 모은 문서다. 원본은 코드의 상수이며, 값이 바뀌면 이 문서도 함께 고친다. (기준: 2026-09-09)

## AI 계정

어드민이 만들어 운영하는 자동 응답 계정이다. 앱에서는 일반 회원과 같은 형태로 보이며, 자동 응답 계정의 존재는 이용약관에 고지한다.

| 항목 | 값 | 위치 |
| --- | --- | --- |
| 계정 | `member` 행(role `AI`) + `ai_persona` 행. 전화번호는 `AI-` 뒤 13자 무작위라 인증번호와 로그인이 불가능하다 | `Member.generateAiPhoneNumber`, `AiPersona` |
| 시스템 프롬프트 | 4,000자, 자유 서술 | `AiPersona.SYSTEM_PROMPT_MAX_LENGTH` |
| 응답 지연 | 0~3,600초 사이 최소, 최대 (기본 10초~3분) | `AiPersona.REPLY_DELAY_MAX_SECONDS` |
| 활동 시간 | 한국 시간 시작, 끝 시각 (기본 08시~01시). 끝이 시작보다 작으면 자정을 넘기고, 같으면 하루 종일 | `AiPersona.isActiveAt` |
| 하루 응답 한도 | 계정당 0~10,000 (기본 500) | `AiPersona.DAILY_REPLY_LIMIT_MAX` |
| 위치 갱신 | 좌표는 고정, 활동 시간 중 20분~3시간 무작위 간격으로 `located_at`만 갱신. 활동 시간 밖이면 다음 시작 뒤 3시간 안으로 미룸. 1분마다 확인 | `AiLocationRefresher` |
| 사진 | 회원 프로필 사진과 같은 규칙, 어드민 브라우저가 R2에 직접 PUT | `AdminAiMemberController` |
| 쪽지, 포인트, 랭킹 | 일반 회원과 동일 (첫 쪽지 15포인트 차감, 좋아요 랭킹 포함) | - |
| 삭제 | 어드민 삭제는 회원 탈퇴 절차 + 페르소나 행 삭제 | `AiMemberService.withdraw` |
| 응답 트리거 | 상대가 보낸 메시지의 커밋 후 이벤트로 `ai_reply_job`(방당 1행)에 upsert. 연달아 보내면 기한만 뒤로 밀린다 | `AiReplyListener`, `AiReplyJobService` |
| 응답 폴링 | 5초마다 기한 지난 작업 20개씩. LLM 호출은 트랜잭션 밖 | `AiReplyScheduler` |
| 문맥 | 방의 최근 메시지 30건 중 최신부터 합쳐 1,500자까지(마지막 1건은 항상), 메시지당 300자, 자기소개는 200자. 사진과 동영상은 `[사진]`, `[동영상]`으로만 | `AiReplyContext.MAX_MESSAGES`, `AiPromptBuilder.CONTEXT_MAX_CHARS/MESSAGE_MAX_CHARS/BIO_MAX_CHARS` |
| 프롬프트 순서 | 규칙, 페르소나, 너 자신(AI마다 고정, 캐시 대상) 뒤에 대화 상대, 언어, 시각. 상대 블록은 "상대를 부를 때는 그 닉네임만 쓴다"를 문장으로 명시 | `AiPromptBuilder` |
| 응답 언어 | 상대 회원의 언어 설정 | `AiPromptBuilder` |
| 응답 한도 | 방당 하루 100회, AI당 페르소나 설정, 전체 하루 2,000회. 전체 한도에 처음 걸릴 때 하루 한 번 에러 로그(디스코드) | `AiReplyContextService` |
| 활동 시간 밖 | 답하지 않고 다음 활동 시작 뒤 응답 지연 안으로 미룸. 페르소나를 저장하면 미뤄진 작업을 새 응답 지연 안으로 당겨 바뀐 활동 시간으로 다시 판단 | `AiReplyDecision.Postpone`, `AiReplyJobRepository.pullForward` |
| 정지된 AI | 서비스 정지 중이면 답하지 않고 작업을 버림. 멈추려면 비활성 토글이 기본 | `AiReplyContextService` |
| 다시 말 걸기 | AI가 마지막으로 말한 뒤 상대가 2일 이상 14일 이내로 조용한 방에 한 시간마다 최대 20개씩, 한 시간 안에 흩어 먼저 말을 건다. 같은 침묵에는 한 번만, 상대가 답한 뒤 다시 조용해지면 다시. 활동 시간, 한도, 로그는 일반 응답과 같음 | `AiNudgeScheduler`, `AiReplyJobService.NUDGE_*` |
| 대화 기억 | 방마다 요약 한 문단(500자 이내)을 `ai_room_memory`에 둔다. 마지막 요약 뒤 메시지 20건이 쌓이면 답장 직후 이전 요약과 새 메시지(최대 60건)로 갱신. 프롬프트의 자기 프로필 뒤에 들어감. 요약 호출은 로그에 SUMMARY로 남기되 응답 수와 한도에는 세지 않음. 방이 지워지면 새벽 정리 때 함께 삭제 | `AiMemoryService`, `AiRoomMemory` |
| 대시보드 | 가입, 탈퇴, 성별 분포 통계에서 AI 계정은 뺌 | `MemberAdminRepository.NOT_AI` |
| 실패 재시도 | 5분 뒤, 3회까지. 이후 작업 삭제 | `AiReplyJob.MAX_ATTEMPTS/RETRY_DELAY` |
| 응답 길이 | 1,000자로 자름 (채팅 메시지 한도) | `OpenAiReplyGenerator` |
| 모델 | `AI_CHAT_MODEL`이 있으면 그 모델, 없으면 검수와 같은 기본 모델. 키가 없으면 응답 안 함 | `AiChatProperties`, `DisabledReplyGenerator` |
| 응답 로그 | 응답마다 `ai_reply_log`에 토큰 수와 모델을 남긴다. 한도 집계와 어드민 통계(오늘, 누적)의 근거 | `AiReplyLog`, `AiReplyLogAdminRepository` |
| 테스트 대화 | 어드민 상세에서 저장하지 않는 대화. 상대는 30세 이성 "테스터", 언어 선택 가능, 폼의 프롬프트 초안으로 답함. 한도에 세지 않음 | `AiTestChatService` |

## 보존 기간과 정리 스케줄

전부 한국 시간 기준이고, 삭제는 DB 커밋 후 R2 파일을 지운다.

| 시각 | 작업 | 보존 기간 |
| --- | --- | --- |
| 04:00 | 고아 업로드 정리 | 1일 |
| 04:30 | 나간 채팅방 (대화, 사진 포함) | 90일 |
| 04:35 | 삭제된 피드 | 90일 |
| 04:40 | 탈퇴 회원 (사진, 닉네임 이력 포함) | 90일 |
| 04:45 | 삭제된 고민 글과 댓글, 처리된 신고 (미처리는 보존) | 90일 |
| 04:50 | 접속 로그, 만료된 정지 기록 | 90일 / 365일 |
| 04:55 | 인증번호 기록, 보상 이력(출석, 접속, 광고) | 90일 |
| 05:10 | AI 응답 로그 | 90일 |
| 9~21시 3시간 간격 | 피드 알림 발송 | - |

스케줄러에는 분산 락이 없다. 단일 인스턴스 전제이며, 스케일아웃 시 ShedLock을 붙이기로 했다.
