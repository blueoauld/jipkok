# 제약 조건

집콕 전체의 형식 규칙, 한도, 보존 기간, 스케줄, 시스템 상한을 모은 문서다. 원본은 코드의 상수이며, 값이 바뀌면 이 문서도 함께 고친다. (기준: 2026-09-09)

## AI 계정

어드민이 만들어 운영하는 자동 응답 계정이다. 앱에서는 일반 회원과 같은 형태로 보이며, 자동 응답 계정의 존재는 이용약관에 고지한다.

| 항목 | 값 | 위치 |
| --- | --- | --- |
| 계정 | `member` 행(role `AI`) + `ai_persona` 행. 전화번호는 `AI-` 뒤 13자 무작위라 인증번호와 로그인이 불가능하다 | `Member.generateAiPhoneNumber`, `AiPersona` |
| 시스템 프롬프트 | 4,000자, 자유 서술 | `AiPersona.SYSTEM_PROMPT_MAX_LENGTH` |
| 응답 지연 | 0~3,600초 사이 최소, 최대 (기본 10초~3분) | `AiPersona.REPLY_DELAY_MAX_SECONDS` |
| 활동 시간 | 한국 시간 시작, 끝 시각 (기본 08시~01시). 끝이 시작보다 작으면 자정을 넘기고, 같으면 하루 종일 | `AiPersona.isActiveAt` |
| 하루 응답 한도 | 계정당 0~10,000 (기본 500) | `AiPersona.DAILY_REPLY_LIMIT_MAX` |
| 위치 갱신 | 좌표는 고정, 활동 시간 중 20분~3시간 무작위 간격으로 `located_at`만 갱신. 활동 시간 밖이면 다음 시작 뒤 3시간 안으로 미룸. 1분마다 확인 | `AiLocationRefresher` |
| 사진 | 회원 프로필 사진과 같은 규칙, 어드민 브라우저가 R2에 직접 PUT | `AdminAiMemberController` |
| 쪽지, 포인트, 랭킹 | 일반 회원과 동일 (AI에게 보내는 첫 쪽지 15포인트 차감, 좋아요 랭킹 포함). AI가 발신자인 첫 쪽지는 포인트를 차감하지 않음 | `ChatNoteService.openRoom` |
| 삭제 | 어드민 삭제는 회원 탈퇴 절차 + 페르소나 행 삭제 | `AiMemberService.withdraw` |
| 응답 트리거 | 상대가 보낸 메시지의 커밋 후 이벤트로 `ai_reply_job`(방당 1행)에 upsert. 연달아 보내면 기한만 뒤로 밀린다 | `AiReplyListener`, `AiReplyJobService` |
| 응답 폴링 | 5초마다 기한 지난 작업 20개씩. LLM 호출은 트랜잭션 밖 | `AiReplyScheduler` |
| 무응답 | 답장 프롬프트에만 "상대 말이 맞장구뿐이면, 특히 작별 인사 뒤의 맞장구면 답하지 않고 `[무응답]`만 쓴다"를 넣는다. 그 표시가 오면 메시지를 보내지 않고 받은 메시지까지 읽음 처리한 뒤 로그에 SKIP으로 남긴다. 모델을 부른 것이라 하루 한도와 어드민 응답 수에는 응답처럼 센다 | `AiPromptBuilder.NO_REPLY`, `AiReplyJobService.skip` |
| 되풀이 표현 | 답장 프롬프트에 AI의 최근 메시지 10개에서 이미 쓴 돌봄 문구(푹 쉬, 무리하지, 챙겨 먹, 챙겨 드, 따뜻한, 조심히, 좋은 밤, 좋은 꿈, 잘 자)를 짚어 다시 쓰지 말라고 넣는다. 다시 만드는 호출은 하지 않는다 | `AiPromptBuilder.REPEAT_WATCHED_PHRASES/REPEAT_WATCH_MESSAGES` |
| 말풍선 | 답장, 다시 말 걸기, 먼저 인사는 문장 끝(`.`, `?`, `!`, `…` 뒤 공백)과 줄바꿈에서 나눠 말풍선 3개까지 보내고, 넘치는 문장은 마지막 말풍선에 붙인다. 말풍선 끝 마침표 하나는 떼고 말줄임은 둔다. 첫 말풍선은 바로 보내고 나머지는 `ai_reply_bubble`에 글자당 0.1초(1~3초로 자름)에 0.5초 이내 무작위를 더한 간격으로 차례로 예약해 1초마다 보낸다. 방이 없거나 기한보다 10분 넘게 밀렸으면 버리고, 보내다 실패하면 재시도 없이 버린다. 로그와 한도는 답 하나로 세고 로그의 메시지는 첫 말풍선이다 | `splitBubbles`, `AiReplyBubbleService`, `AiReplyBubbleScheduler` |
| 문맥 | 방의 최근 메시지 30건 중 최신부터 합쳐 1,500자까지(마지막 1건은 항상), 메시지당 300자, 자기소개는 200자. 사진과 동영상은 `[사진]`, `[동영상]`으로 적고, 아래 사진 보기에 해당하는 한 장만 이미지를 함께 붙인다. 메시지 사이가 한 시간 넘게 비면 그 자리에 "(7시간 뒤)" 같은 시스템 메시지를 넣는다 | `AiReplyContext.MAX_MESSAGES`, `AiPromptBuilder.CONTEXT_MAX_CHARS/MESSAGE_MAX_CHARS/BIO_MAX_CHARS/TIME_NOTE_AFTER` |
| 사진 보기 | 답장할 때 AI가 마지막으로 말한 뒤 상대가 보낸 사진과 동영상 중 가장 최근 것 하나만 모델에 이미지로 넘긴다(동영상은 썸네일). 서명 URL(10분)을 OpenAI 검수 API(`omni-moderation-latest`)에 먼저 보내 걸리거나 검수에 실패하면 넘기지 않고, 이미지를 넣은 요청이 실패하면 이미지 없이 다시 만든다. 이미 답한 사진은 다시 넘기지 않고 요약에는 넘기지 않는다 | `imageMessageOf`, `OpenAiImageModerator`, `OpenAiReplyGenerator` |
| 프롬프트 순서 | 규칙, 페르소나, 너 자신(AI마다 고정, 캐시 대상) 뒤에 대화 상대, 언어, 시각(요일 포함). 답장이면 상대의 마지막 말이 한 시간 넘게 지났을 때 언제 왔는지와 지금 봤다는 것을 덧붙이고, AI가 아직 말한 적 없고 대화 기억도 없는 방이면 상대가 먼저 말을 걸었다는 것을 덧붙인다. 상대 블록은 "너 자신을 그 닉네임으로 부르지 않는다"를 문장으로 명시하고, 양쪽 프로필의 빈 코멘트와 자기소개는 "없음"으로 적는다. 먼저 인사는 상대 코멘트와 자기소개가 모두 없으면 프로필을 언급하라고 하지 않는다. 너 자신 블록에는 AI의 프로필 사진과 비밀사진 장수를 적고, 비밀사진이 있으면 따로 공개해 준 사람만 볼 수 있어 다른 사람에게는 잠긴 채 장수만 보인다는 것과 아직 아무에게도 공개하지 않았다는 것을 덧붙인다(AI 계정은 공개해 줄 수단이 없다) | `AiPromptBuilder`, `AiPhotoCounts` |
| 응답 한도 | 방당 하루 100회, AI당 페르소나 설정, 전체 하루 2,000회. 한국 날짜로 초기화된다. 닿으면 작업을 버리지 않고 다음 날 활동 시작 뒤 한 시간 안으로 흩어 미루므로, 그사이 받은 말에는 다음 날 답한다. 전체 한도에 처음 걸릴 때 하루 한 번 에러 로그(디스코드) | `AiReplyContextService` |
| 활동 시간 밖 | 답하지 않고 다음 활동 시작 뒤 응답 지연 안으로 미룸. 페르소나를 저장하면 미뤄진 작업을 새 응답 지연 안으로 당겨 바뀐 활동 시간으로 다시 판단 | `AiReplyDecision.Postpone`, `AiReplyJobRepository.pullForward` |
| 정지된 AI | 서비스 정지 중이면 답하지 않고 작업을 버림. 멈추려면 비활성 토글이 기본 | `AiReplyContextService` |
| 다시 말 걸기 | AI가 마지막으로 말한 뒤 상대가 2일 이상 14일 이내로 조용한 방에 한 시간마다 최대 20개씩, 한 시간 안에 흩어 먼저 말을 건다. 같은 침묵에는 한 번만, 상대가 답한 뒤 다시 조용해지면 다시. 활동 시간, 한도, 로그는 일반 응답과 같음 | `AiNudgeScheduler`, `AiReplyJobService.NUDGE_*` |
| 먼저 인사 | 가입 후 10분~3일 사이의 쪽지를 받는 일반 회원을 성별과 상관없이 10분마다 50명씩 찾아 `ai_greeting_job`(회원당 한 행)에 10분~2시간 뒤로 예약. 실행 시 탈퇴, 쪽지 수신 끔, 정지, 가입 3일 경과면 포기하고 아직 하트비트가 없으면(`located_at` null) 한 시간 뒤로 미룸. 인사가 켜진 이성 AI 중 상대와 가까운 5명에서 무작위로 고르고, 상대가 위치를 껐으면 거리 없이 전체에서 무작위 5명. 이때 프롬프트에 거리 얘기를 꺼내지 말라고 넣음. 방이 있거나 차단(회원, 번호) 관계, 정지, 하루 인사 한도(페르소나, 기본 20, 최대 1,000)에 닿은 AI는 뺌. 전체 하루 200회를 넘으면 내일로, AI 활동 시간 밖이면 다음 시작 뒤로 미룸. 전송은 쪽지 서비스를 그대로 타고 차단, 수신 끔 같은 업무 예외는 재시도 없이 포기, 그 밖의 실패는 5분 뒤 3회까지. 로그 종류 GREETING으로 응답 한도에 포함. 보낸 뒤 답장이 오면 일반 응답, 조용하면 다시 말 걸기로 이어짐. 보낸 행과 포기한 행은 재발송 방지용으로 남기고 탈퇴 시 삭제 | `AiGreetingJobService`, `AiGreetingContextService`, `AiGreetingScheduler` |
| 대화 기억 | 방마다 AI 자신의 메모(상대에 대해 알게 된 것, AI가 자기에 대해 말한 것과 약속, 분위기와 마지막 화제를 문단으로 나눠 500자 이내)를 `ai_room_memory`에 둔다. 마지막 갱신 뒤 메시지 20건이 쌓이면 답장 직후 이전 메모와 새 메시지(최대 60건)로 갱신. 프롬프트의 자기 프로필 뒤에 들어감. 요약 호출은 로그에 SUMMARY로 남기되 응답 수와 한도에는 세지 않음. 방이 지워지면 새벽 정리 때 함께 삭제 | `AiMemoryService`, `AiRoomMemory` |
| 대시보드 | 가입, 탈퇴, 성별 분포 통계에서 AI 계정은 뺌 | `MemberAdminRepository.NOT_AI` |
| 피드 알림 | AI 계정은 대상에서 뺌 (기기 토큰이 없어 원래 나가지 않지만 조회에서도 제외) | `FeedReminderRepository` |
| 실패 재시도 | 5분 뒤, 3회까지. 이후 작업 삭제 | `AiReplyJob.MAX_ATTEMPTS/RETRY_DELAY` |
| 호출 타임아웃 | 요청 하나에 30초, 클라이언트 재시도 1회. 위의 작업 재시도와는 별개다 | `application.yaml spring.ai.openai` |
| 답할 언어 | 상대가 최근에 쓴 글자(한글, 가나, 한자, 라틴 순)로 정하고, 글자로 알 수 없으면 계정 언어. 먼저 인사는 주고받은 말이 없어 계정 언어. 대화 기억 요약도 같은 언어로 쓴다 | `AiLanguage.detectLanguage` |
| 언어 검사 | 답에 그 언어의 문자와 라틴, 공통 문자(숫자, 문장부호, 이모지) 밖의 글자가 있거나, 영어가 아닌 답에 소문자가 든 세 글자 이상 영단어가 있거나, 그 언어의 글자가 하나도 없으면 한 번만 다시 만든다. 그래도 어긋나면 어긋난 곳이 처음 나온 자리에서 잘라 앞부분만 보내고, 앞부분에 그 언어 글자가 없으면 보내지 않는다 | `AiLanguage.matchesLanguage/cutAtForeign`, `OpenAiReplyGenerator` |
| 샘플링 온도 | 주지 않는다. gpt-5 계열은 기본값 1만 받고 다른 값을 보내면 400으로 거절한다 | `OpenAiReplyGenerator` |
| 응답 길이 | 출력 토큰을 응답 300, 요약 800으로 제한하고, 받은 뒤 응답 1,000자와 요약 500자로 자름 | `OpenAiReplyGenerator.REPLY_MAX_TOKENS/SUMMARY_MAX_TOKENS` |
| 모델 | `AI_CHAT_MODEL`이 있으면 그 모델, 없으면 검수와 같은 기본 모델. 키가 없으면 응답 안 함 | `AiChatProperties`, `DisabledReplyGenerator` |
| 응답 로그 | 응답마다 `ai_reply_log`에 토큰 수(입력, 출력, 캐시에서 읽은 입력), 모델, 답한 언어, 언어가 어긋나 다시 만들었는지를 남긴다. 요청에는 AI별 `prompt_cache_key`(`ai-{memberId}`)를 붙인다. 한도 집계와 어드민 통계(오늘, 누적)의 근거 | `AiReplyLog`, `AiReplyLogAdminRepository` |
| 테스트 대화 | 어드민 상세에서 저장하지 않는 대화. 상대는 30세 이성 "테스터", 언어 선택 가능, 폼의 프롬프트 초안으로 답함. 답은 실제로 나갈 말풍선을 줄바꿈으로 이어 보여 준다. 한도에 세지 않음 | `AiTestChatService` |

## 보존 기간과 정리 스케줄

전부 한국 시간 기준이고, 삭제는 DB 커밋 후 R2 파일을 지운다.

| 시각 | 작업 | 보존 기간 |
| --- | --- | --- |
| 04:00 | 고아 업로드 정리 | 1일 |
| 04:30 | 나간 채팅방 (대화, 사진 포함) | 90일 |
| 04:35 | 삭제된 피드 | 90일 |
| 04:40 | 탈퇴 회원 (사진, 닉네임 이력 포함) | 90일 |
| 04:45 | 삭제된 고민 글과 댓글, 처리된 신고 (미처리는 보존) | 90일 |
| 04:50 | 접속 로그, 만료된 정지 기록 | 90일 / 365일 |
| 04:55 | 인증번호 기록, 보상 이력(출석, 접속, 광고) | 90일 |
| 05:10 | AI 응답 로그 | 90일 |
| 9~21시 3시간 간격 | 피드 알림 발송 | - |

스케줄러에는 분산 락이 없다. 단일 인스턴스 전제이며, 스케일아웃 시 ShedLock을 붙이기로 했다. 예약 작업은 스레드 넷을 나눠 쓴다. AI 응답과 먼저 인사 폴링이 OpenAI 호출로 한 스레드를 오래 잡아도 나머지 정리 배치가 멈추지 않게 한 값이다.
