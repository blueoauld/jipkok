# 수사 협조

수사기관이 회원 정보를 요청했을 때 따르는 절차다. 잘못 제공하면 개인정보보호법 위반으로 사업자가 책임지므로, 급해 보여도 이 순서를 건너뛰지 않는다.

> 이 문서는 내부 기준선이다. 실제 요청을 받기 전에 변호사나 한국인터넷진흥원
> 개인정보 침해신고센터 (국번 없이 118)로 한 번 검증하는 것이 좋다.

## 처리 절차

### 1. 접수

`hello@jipkok.app` 으로 받은 공문만 처리한다. 전화나 구두로 요청받으면 다음과 같이 답하고 끊는다.

> 개인정보 제공은 공문으로만 처리하고 있습니다. 요청서를 hello@jipkok.app 으로
> 보내주시면 검토 후 회신드리겠습니다.

### 2. 진위 확인

공문에 적힌 연락처로 걸지 않는다. 기관 이름을 직접 검색해 찾은 대표번호로 전화해 요청 사실과 담당자를 확인한다.

### 3. 서류 등급 확인

요청하는 정보에 따라 필요한 서류가 다르다. 서류가 모자라면 제공하지 않고, 어떤 서류가 필요한지 안내해 회신한다.

| 요청 정보                                 | 필요한 서류  | 근거                                             |
|-------------------------------------------|--------------|--------------------------------------------------|
| 가입자 정보 (휴대폰 번호, 닉네임, 가입일) | 공문         | 전기통신사업법 83조. 제공 여부는 사업자 재량이다 |
| 접속 기록 (IP 주소, 접속 시각, 기기)      | 법원 허가서  | 통신비밀보호법상 통신사실확인자료                |
| 대화 내용, 사진                           | 압수수색영장 | 내용물은 영장 없이 제공할 수 없다                |

판단이 서지 않으면 제공하지 않는다. 거절은 되돌릴 수 있지만 제공은 되돌릴 수 없다.

### 4. 조회

요청서에 적힌 항목과 기간만 조회한다. 곁다리로 보이는 정보는 함께 보내지 않는다.

특정 시각에 특정 닉네임을 쓰던 회원을 찾을 때는 닉네임 이력을 먼저 조회한다.

```sql
-- 그 시각에 해당 닉네임을 쓰던 회원
select member_id
from nickname_history
where nickname = :nickname
  and created_at <= :moment
order by created_at desc
limit 1;

-- 그 회원의 접속 기록
select accessed_on, ip_address, platform, device_name, created_at
from access_log
where member_id = :member_id
  and accessed_on between :from and :to;
```

보관 기간이 지난 정보는 없다. 없으면 없다고 회신한다.

| 정보             | 보관 기간                             |
|------------------|---------------------------------------|
| 접속 기록        | 90일                                  |
| 신고 내용과 증거 | 접수 후 90일                          |
| 탈퇴 회원 정보   | 탈퇴 후 90일                          |
| 닉네임 이력      | 회원 파기 시까지                      |
| 대화 내용        | 방을 나가면 즉시 삭제되어 남지 않는다 |

### 5. 기록

제공했든 거절했든 아래 대장에 남긴다. 거절 기록은 함부로 제공하지 않았다는 근거가 된다.
